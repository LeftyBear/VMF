## 2. Checklist use

Use exactly one readiness result for each checklist item:

- `[ ] READY-DOCUMENTED` — the required documentary content is present, exact, attributable, bounded, and internally consistent within the declared review scope.
- `[ ] NOT READY / WITHHOLD` — a required non-conflicting item is absent, incomplete, ambiguous, stale, expired, unattributable, unauthorized, or otherwise ineligible.
- `[ ] CONFLICT-HOLD / SAFE-STOP` — a conflict exists with an authoritative source, another field or unit, a controlling boundary, or a claimed authority.
- `[ ] NOT APPLICABLE WITH AUTHORITY BASIS` — the item is inapplicable only under an exact attributable authority basis and bounded scope.

`READY-DOCUMENTED` is a preparation label only. It is not `PASS`, readiness for technical execution, submission authorization, `ACCEPTED FOR DOCUMENTARY INTAKE`, gap resolution, inventory completion, evidence acceptance, control-effectiveness confirmation, security clearance, continuation authorization, command authorization, technical execution GO, or an execution instruction.

A gap unit may be marked ready for package assembly only when every applicable item for that unit is `READY-DOCUMENTED` or has a valid `NOT APPLICABLE WITH AUTHORITY BASIS`, and no item is `NOT READY / WITHHOLD` or `CONFLICT-HOLD / SAFE-STOP`. Package readiness requires the same condition for every included unit and every package-level item. This rule does not authorize submission.

## 3. Package-level readiness checklist

### 3.1 Package identity and scope

- [ ] One unique documentary Submission ID is present for the bounded package.
- [ ] One exact submission date in `YYYY-MM-DD` form is present and is not substituted for a source-record, review, validity, or technical-event date.
- [ ] Addressed and unaddressed gap lists are complete, mutually exclusive, and use exact P9-145 controlling gap IDs.
- [ ] Every applicable P9-146 ML label is recorded as secondary traceability only, or `none` is supported by an explicit rationale.
- [ ] The exact affected source records, inventory entries, candidates, controls, commands, evidence packages, decisions, or proposed activities are named and bounded.
- [ ] Every included gap unit is independently reviewable; omitted or withheld units are listed under `Gaps not addressed` rather than left blank or represented by `TBD`.

### 3.2 Common required fields

- [ ] The package identifies the accountable owner or exact authoritative role, the decision or statement supplied, and the exact authority basis and scope.
- [ ] Exact authoritative source identifiers and the specific statements relied upon are supplied.
- [ ] Supplied values, decisions, limitations, and any justified `not applicable` determinations are explicit.
- [ ] All applicable dates, versions, effective periods, expiry dates, review dates, validity limits, or authoritative no-version statements are explicit and attributable.
- [ ] Preconditions, residual limitations, exceptions, dependencies, exclusions, and prohibited uses are explicit.
- [ ] Referenced attachments are identified by exact documentary reference and purpose, or the package states `none`.
- [ ] Shared material is mapped expressly to every applicable controlling gap without concealing a gap-specific missing field.
- [ ] The package conflict declaration covers its exact review scope, source set, submitted fields, controlling boundaries, claimed authorities, and stale, expired, ambiguous, or superseded material.
- [ ] The attestation identifies the submitter, represented owner or authority, exact authority source and scope, limitations, independence boundaries, attestation date, and documentary signature reference.

### 3.3 Package integrity and boundary

- [ ] Candidate identity and exact scope are consistent across all included candidate-specific units.
- [ ] Security, continuation, technical-decision, control, command-authorization, execution-instruction, and intake-review authorities remain separate and are not inherited or merged.
- [ ] Cross-unit references are explicit and do not substitute for required unit-specific content.
- [ ] No value has been inferred or reconstructed from context, filenames, chronology, authorship, repository location, prior practice, another unit, or an attachment.
- [ ] Referenced attachments remain opaque and have not been opened or technically inspected to complete the package.
- [ ] Package preparation requires no external lookup, external contact, artifact discovery or inspection, technical validation, evidence generation or refresh, Avast interaction, or command execution.
- [ ] The P9-149 intake-review section remains blank; review date, per-gap completeness result, reasons, and confirmed source states remain `not assessed`.
- [ ] Intake disposition remains `NOT ASSESSED` and has not been predicted or pre-populated.
- [ ] Owner input submission state remains `NOT SUBMITTED` unless and until a separate explicit submission action is authorized and performed.
- [ ] The package contains no execution instruction and makes no claim of submission, intake acceptance, gap closure, inventory completion, evidence acceptance, control effectiveness, security clearance, technical readiness, authorization inheritance, or technical execution GO.

## 6. Fail-closed conditions

Immediately mark the affected unit `NOT READY / WITHHOLD`, or the whole package when the condition is package-wide. If the condition is a conflict, mark `CONFLICT-HOLD / SAFE-STOP` instead.

1. Any mandatory value is missing, blank, `TBD`, unknown, illegible, inferred, reconstructed, unattributable, unauthorized, stale, expired, or broader than the cited authority.
2. Any conflict exists with an authoritative source, another field or unit, a controlling boundary, or a claimed authority.
3. An ML label, predecessor ID, inventory item, control ID, allowlist ID, or evidence ID substitutes for an exact P9-145 controlling gap ID.
4. A candidate, command, control, evidence package, source set, decision, or activity is generic, multiple, conditional, or insufficiently bounded.
5. Completion requires external contact, external lookup, artifact discovery or inspection, technical validation, evidence generation or refresh, Avast interaction, or command execution.
6. One authority purports to supply another independent authority's statement or decision.
7. The package contains an execution instruction, a pre-populated intake disposition, a GO claim, or a substantive acceptance, readiness, completion, or resolution claim.
8. P9-94 is relied upon, or P9-130/P9-135 is proposed through any rerun, reconstruction, approximation, wrapper, rename, equivalent, or materially similar route.
9. A dependent unit is proposed before its prerequisite is separately supplied and documentary-eligible.
10. Any P9-149 intake-review field is populated or owner input is represented as submitted without separate explicit authority and the actual submission action.

No fail-closed condition may be cured through inference, omission, repackaging, permissive interpretation, or partial credit. A withheld or held unit remains outside the package. If the package cannot remain exact and internally consistent without that unit, withhold the entire package.

This checklist does not assign a P9-148 intake disposition. A later separately authorized intake review must apply P9-148 conflict precedence: conflict produces `CONFLICT-HOLD / SAFE-STOP`; without conflict, an unsatisfied mandatory criterion produces `NOT ACCEPTED FOR DOCUMENTARY INTAKE`; only a conflict-free submission satisfying every applicable criterion may receive `ACCEPTED FOR DOCUMENTARY INTAKE`.
